# 应用宝上架 —— 图标一致性问题（问题1）排查与修复记录

> 场景：应用宝审核驳回【问题1-体验问题】“上传图标与安装后实际图标不一致，请修改后重新提交”。
> 触发时间/版本：v1.0.4（AppID `__UNI__8969615`，包名 `com.xingye.hoshino`）

## 一、最终结论（先看这个）

- **代码和 APK 里没有问题**：APK 内实际桌面图标 = 仓库 `static/icons/` 这套“浅绿底 + 深绿色符号”的图标。
- **问题出在应用宝后台上传的那张图**：后台的图和 APK 里的图不是同一张（常见是传了旧图/错图）。
- **修复动作**：把应用宝后台图标换成与 APK 一致的图（推荐 `static/icons/512x512.png`），保存后重新提交。

## 二、正确图标是什么、在哪

**当前正确图标 = 仓库 `static/icons/` 全套（浅绿底、无圆角透明区域、绿色符号）**，从 2026-07-01 起未更换过设计。

关键路径：
- 商店图标（后台上传用，本项目约定）：`static/icons/512x512.png`（由 `static/icons/1024x1024.png` 生成）
- Android 桌面图标（mipmap）：`static/icons/{72,96,144,192}x{72,96,144,192}.png`
- iOS 图标：`static/icons/20x20.png` ~ `1024x1024.png`

> 更换图标规范：**只改 `static/icons/*`，不要手改离线工程 `res/`**。离线工程的 mipmap 由打包脚本自动同步（见第四条）。

## 三、本次排查怎么定位的（流程可复用）

1. 比对哈希 + 像素：`static/icons/`、`unpackage/res/icons/`、HBuilderX `.manifest` 缓存、离线工程 `mipmap-*/icon.png` 都应为同一设计。
2. 用 `aapt dump badging base.apk` 拿到 APK 实际应用图标资源名（离线打包会混淆，如 `res/_J.png / mS.png / ly.png / hW.png`）。
3. 从 APK 提取这 4 个图标，与仓库 `static/icons/` 用 pngjs 做像素级对比，**0% 差异 = 一致**。
4. 至此确认“APK 对、仓库对”，排除代码层，判定为后台上传图不对。

> APK 内图标 MD5 与仓库不同是正常现象（打包时 PNG 被压缩），需做像素级对比而非对比 MD5。
