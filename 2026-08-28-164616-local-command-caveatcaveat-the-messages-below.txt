  ---
  一、官方文档 app-privacy-android.html 的核心要求

  根据搜索到的官方同源内容，这篇文档要求做到以下几点：

  1. 隐私弹窗必须用 template 模式

  - 文件：项目根目录/androidPrivacy.json
  - 关键字段：
  {
    "version": "1",
    "prompt": "template",
    "title": "服务协议和隐私政策",
    "message": "......<br>...IMEI、Android ID、DEVICE_ID、IDFA、IMSI、OAID...",
    "buttonAccept": "同意并接受",
    "buttonRefuse": "暂不同意",
    "hrefLoader": "system",
    "backToExit": "false",
    "second": { ... },
    "disagreeMode": { ... },
    "styles": { ... }
  }
  - 不能用自定义原生弹窗。文档和官方问答反复强调：只有 template
  模式才能在基座层正确拦截 SDK 在同意前的初始化。

  2. 隐私文案里必须明确列出 OAID

  message 里要包含：

  ▎ IMEI / Android ID / DEVICE_ID / IDFA / IMSI / OAID 等设备标识信息

  这一点你在 [[privacy-template-oaid-fix]] 里已经做了（改了 5 个文件）。

  3. 版本要求

  - 云端打包：HBuilderX 3.6.1+
  - OAID 合规专项：HBuilderX 3.6.8+
  - 如果完全不需要 OAID：manifest.json → android → "enableOAID": false（需
  HBuilderX 3.8.5+），此后 plus.device.getOAID 返回空字符串。

  4. 不同意模式 disagreeMode

  用户点「暂不同意」后，App 仍可进入基础模式，但受限 API（包括
  plus.device.getOAID、plus.ad.xxx 等）会被拦截。

  ---
  二、为什么单单照做官方文档，未必能解决你的问题

  你的问题不是「没弹框」或「文案没写 OAID」，而是：

  ▎ SDK 5.24 在 Activity onCreate 的 Runnable（字符串 "ba_pull"）里，先调了 
  ▎ ADHandler.pull → 触发 MdidSdkHelper.InitSdk 采 OAID，然后才做 
  ▎ AppRuntime.hasPrivacyForNotShown 判断。

  也就是说：
  - template 弹窗管的是业务层/JS 层调用。
  - ba_pull 发生在基座原生层启动早期，隐私框还没出来就已经初始化完了。
  - 社区反馈里有人验证：即使配了 androidPrivacy.json + template， fresh install
  下 OAID 还是会被写入 dcloud-ads.xml 和 pdr.xml。

  这是 DCloud 官方 Q&A
  里被标记/回复过的已知问题，根因在基座，不是配置能完全兜住的。
